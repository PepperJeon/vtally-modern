The real page is one full-bleed surface: 100vw × 100dvh, no nav, no card. Each frame below is one state at phone proportions. Fill colours are the literal LED rgb() values from ColorScheme.ts, multiplied per channel by the brightness fraction — the same sRGB multiply the firmware applies to the LED's PWM duty cycle, so screen and lamp agree.

Why the dimmed frame is the important one. webtally.spec.ts asserts that the data-brightness attribute changes — nothing asserts the pixel. The attribute can read 0.4 while the screen paints full red. The design's answer is that background and text colour are both derived from one computed value, so a broken dim inverts the text and announces itself; the test's answer is one getComputedStyle(el).backgroundColor assertion. Both, not either.
